# جلسه ۷-۵ — امکانات پیشرفته PivotTable

## هدف جلسه

تا اینجا PivotTable را برای خلاصه‌سازی و مقایسه استفاده کردیم. اکنون چند ابزار مهم‌تر را می‌شناسیم که Pivot را برای گزارش‌سازی و تحلیل تعاملی قدرتمندتر می‌کنند.

## Calculated Field

گاهی داده خام دقیقاً معیاری را که می‌خواهیم ندارد.

فرض کنید در جدول فروش دو ستون `Revenue` و `Quantity` داریم و می‌خواهیم «میانگین درآمد به ازای هر واحد» را در گزارش محاسبه کنیم.

از **PivotTable Analyze → Fields, Items & Sets → Calculated Field** می‌توان یک فیلد محاسباتی تعریف کرد.

منطق آن تقریباً این است:

```text
Average Revenue per Unit = Revenue / Quantity
```

پس از ساخت، این فیلد می‌تواند در Values استفاده شود.

> **نکته:** اگر محاسبه موردنیاز را می‌توان قبل از ساخت Pivot در دیتاست خام به‌صورت شفاف ایجاد کرد، گاهی بهتر است آن ویژگی را در منبع داده بسازیم. Calculated Field بیشتر برای محاسبات وابسته به ساختار Pivot مفید است.

## Slicer — فیلتر بصری

Slicer یک کنترل بصری برای فیلتر کردن PivotTable است.

مسیر معمول:

**PivotTable Analyze → Insert Slicer**

مثلاً اگر Slicer مربوط به `Region` بسازیم، کاربر می‌تواند با یک کلیک فقط منطقه موردنظر را انتخاب کند.

Slicer نسبت به فهرست فیلتر معمولی دو مزیت مهم دارد:

- وضعیت فیلتر فعلی را واضح نشان می‌دهد.
- برای گزارش‌هایی که کاربر نهایی قرار است با آن‌ها تعامل داشته باشد، استفاده از آن بسیار ساده است.

با نگه داشتن `Ctrl` می‌توان چند مقدار را هم‌زمان انتخاب کرد.

## اتصال یک Slicer به چند PivotTable

اگر چند PivotTable از یک Pivot Cache یا منبع سازگار استفاده کنند، می‌توان یک Slicer را به چند Pivot متصل کرد.

این قابلیت برای داشبورد بسیار مهم است. مثلاً یک Slicer با عنوان `Region` می‌تواند هم جدول فروش و هم نمودار تعداد سفارش را فیلتر کند.

## Timeline

Timeline یک فیلتر بصری مخصوص داده‌های تاریخ است.

برای مثال اگر گزارش چند سال داده دارد، می‌توانیم با Timeline سال، فصل، ماه یا روز را انتخاب کنیم و محدوده زمانی گزارش را تغییر دهیم.

> Timeline برای فیلد Date طراحی شده است؛ اگر تاریخ‌ها به شکل Text ذخیره شده باشند ممکن است عملکرد مورد انتظار را نداشته باشد.

## چند PivotTable از یک منبع

داشتن چند PivotTable از یک Dataset مزیت مهمی دارد.

مثلاً:

```text
Pivot 1 → فروش بر اساس شعبه
Pivot 2 → فروش بر اساس محصول
Pivot 3 → سفارش‌ها بر اساس ماه
Pivot 4 → میانگین مبلغ سفارش
```

هر کدام سؤال متفاوتی را پاسخ می‌دهند و می‌توانند در یک گزارش کنار یکدیگر قرار بگیرند.

## GETPIVOTDATA

وقتی بخواهیم یک مقدار مشخص را از PivotTable در سلول دیگری استفاده کنیم، Excel ممکن است تابع `GETPIVOTDATA` را پیشنهاد دهد.

ساختار ساده آن را می‌توان به‌شکل زیر دید:

```excel
=GETPIVOTDATA("Sum of Amount",$B$4,"Product","Laptop")
```

این تابع به جای وابستگی شدید به آدرس یک سلول، بر اساس فیلدها و آیتم‌های Pivot مقدار موردنظر را استخراج می‌کند.

این ویژگی در ساخت KPIهای سفارشی و داشبوردها مفید است.

> اگر Pivot جابه‌جا شود، ارجاع مستقیم مثل `=F9` ممکن است معنای خودش را از دست بدهد؛ GETPIVOTDATA در سناریوهای مناسب مقاوم‌تر است.

## تمرین

روی Dataset فروش:

1. یک Calculated Field برای `Revenue / Quantity` بسازید.
2. یک Slicer برای `Branch` ایجاد کنید.
3. یک Timeline برای `Date` اضافه کنید.
4. دو PivotTable متفاوت ایجاد و Slicer را به هر دو متصل کنید.
5. مقدار فروش یک محصول خاص را با GETPIVOTDATA در یک سلول KPI نمایش دهید.
