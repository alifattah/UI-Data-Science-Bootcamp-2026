# جلسه ۴ — Missing Data، اصلاح متن و Text to Columns

## 🎯 هدف جلسه

در این جلسه سراغ چند مشکل رایج در داده‌های واقعی می‌رویم: **مقدارهای خالی، ناسازگاری‌های متنی و ستون‌هایی که بیش از یک مفهوم را در خود نگه داشته‌اند.**

---

# ۱. Missing Data چیست؟

Missing Data یعنی برای یک ویژگی مشخص، مقداری در Dataset ثبت نشده است.

مثلاً:

| Customer | City | Age | Amount |
|---|---|---:|---:|
| A101 | Tehran | 31 | 2,400,000 |
| A102 | Shiraz |  | 1,850,000 |
| A103 | Tabriz | 27 |  |

در اینجا `Age` مشتری دوم و `Amount` مشتری سوم خالی است.

اما یک سؤال مهم داریم:

> آیا هر سلول خالی باید حذف شود؟

قطعاً نه.

خالی بودن یک مقدار ممکن است نشان‌دهنده‌ی اطلاعات ثبت‌نشده، غیرقابل‌اعمال بودن ویژگی یا حتی یک مرحله ناقص در Data Collection باشد.

---

# ۲. چه زمانی حذف Row منطقی است؟

فرض کنید می‌خواهیم تحلیل فروش انجام دهیم و ستون `Amount` برای همه سفارش‌ها ضروری است.

اگر Amount یک سفارش خالی باشد و هیچ راه مطمئنی برای پیدا کردن مقدار آن نداشته باشیم، ممکن است آن رکورد برای تحلیل فروش قابل استفاده نباشد.

اما اگر ستون `Customer_Comment` خالی باشد، احتمالاً نمی‌خواهیم سفارش را حذف کنیم؛ چون Comment برای تحلیل اصلی ما ضروری نیست.

پس تصمیم باید بر اساس این سؤال باشد:

> **آیا این مقدار برای سؤال تحلیلی من حیاتی است؟**

---

# ۳. پیدا کردن سلول‌های خالی با Go To Special

یکی از روش‌های سریع Excel برای پیدا کردن سلول‌های خالی:

```text
Home
→ Find & Select
→ Go To Special
→ Blanks
```

پس از انتخاب `Blanks`، Excel سلول‌های خالی محدوده را مشخص می‌کند.

اگر قصد حذف Row داشته باشیم، می‌توان پس از انتخاب سلول‌های خالی از گزینه‌ی Delete و سپس `Entire Row` استفاده کرد.

> ⚠️ **هشدار:** این عملیات حذف واقعی است. قبل از اجرای آن، مطمئن شوید که واقعاً می‌خواهید رکوردها حذف شوند.

---

# ۴. Filter یا Delete؟

دو رویکرد متفاوت داریم.

### Filter
داده‌هایی که شرط را ندارند فقط از نمایش کنار گذاشته می‌شوند؛ خود داده حذف نمی‌شود.

### Delete
رکورد واقعاً از جدول حذف می‌شود.

برای تحلیل اکتشافی، Filter معمولاً انتخاب امن‌تری است؛ چون می‌توانیم ابتدا اثر کار را ببینیم.

مثلاً:

```text
Filter Amount = Blank
→ بررسی رکوردها
→ تصمیم‌گیری
→ سپس در صورت نیاز حذف
```

این رویکرد از اشتباه‌های جبران‌ناپذیر جلوگیری می‌کند.

---

# ۵. ناسازگاری‌های متنی

در داده‌های متنی، گاهی دو مقدار از نظر ظاهری شبیه‌اند اما واقعاً یکسان نیستند.

نمونه کلاسیک در داده فارسی:

```text
کتاب
كتاب
```

ممکن است یکی از این دو با حروف فارسی و دیگری با حروف عربی ثبت شده باشد.

همین مشکل ممکن است برای فاصله‌ها و حروف کوچک/بزرگ انگلیسی هم اتفاق بیفتد:

```text
Tehran
tehran
 Tehran
```

از نظر تحلیلگر شاید هر سه یک شهر باشند، ولی Excel آن‌ها را می‌تواند به‌عنوان رشته‌های متفاوت ببیند.

---

# ۶. Replace برای استانداردسازی

یکی از راه‌های سریع برای اصلاح یک مقدار تکرارشونده استفاده از `Find & Select → Replace` است.

مثلاً اگر در Dataset عبارت اشتباه `Teharn` چندین بار تکرار شده باشد، می‌توان آن را با `Tehran` جایگزین کرد.

برای داده‌های فارسی نیز می‌توان از همین روش برای اصلاح نگارش‌های مشخص استفاده کرد.

> نکته: Replace ابزار قدرتمندی است؛ چون می‌تواند تعداد زیادی رکورد را یک‌باره تغییر دهد. قبل از اجرای Replace، نمونه‌ای از نتایج را بررسی کنید.

---

# ۷. فاصله‌های اضافی

گاهی اختلاف واقعی داده فقط فاصله‌ی ابتدا یا انتهای رشته است:

```text
"Nima"
" Nima"
"Nima "
```

این سه رشته می‌توانند برای برخی عملیات متفاوت رفتار کنند.

در فرمول‌ها نیز با تابع `TRIM` می‌توان فاصله‌های اضافی را تا حد قابل توجهی پاک کرد:

```excel
=TRIM(A2)
```

در Power Query نیز ابزارهایی برای Trim و Clean وجود دارد.

---

# ۸. Text to Columns چیست؟

فرض کنید یک ستون داریم:

```text
2026-09-12 14:35
2026-09-13 09:20
2026-09-14 18:10
```

در این ستون دو مفهوم جدا وجود دارد:

- Date
- Time

اگر تحلیل ما به هر دو به‌صورت جداگانه نیاز داشته باشد، بهتر است آن‌ها را در دو Column مستقل نگهداری کنیم.

یکی از ابزارهای Excel برای این کار `Text to Columns` است.

---

# ۹. تفکیک بر اساس Delimiter

فرض کنید ستون زیر را داریم:

```text
Tehran | Iran
Shiraz | Iran
Tabriz | Iran
```

می‌توانیم:

```text
Data
→ Text to Columns
→ Delimited
```

را انتخاب کنیم و `|` را به‌عنوان Delimiter تعیین کنیم.

خروجی:

| City | Country |
|---|---|
| Tehran | Iran |
| Shiraz | Iran |
| Tabriz | Iran |

---

# ۱۰. تفکیک بر اساس Fixed Width

همیشه جداکننده نداریم.

گاهی ساختار داده بر اساس جایگاه کاراکترها مشخص است. در چنین شرایطی می‌توان از **Fixed Width** استفاده کرد و نقاط شکست را تعیین کرد.

البته در Data Analysis مدرن، اگر قالب منبع قابل تغییر باشد، بهتر است تا جای ممکن داده را از ابتدا در ستون‌های مستقل دریافت کنیم.

---

# ۱۱. یک مثال ترکیبی

فرض کنید فایل مشتریان چنین داده‌ای دارد:

```text
customer_code | full_name | city_country | age
C-101        | Ali Ahmadi | Tehran-Iran | 29
C-102        | Sara Moradi| Shiraz-Iran | 34
```

مشکلات احتمالی:

1. `city_country` دو مفهوم را با هم دارد.
2. نام‌ها ممکن است فاصله اضافی داشته باشند.
3. اگر City در چند شکل نوشته شود، تحلیل شهری دچار مشکل می‌شود.

Workflow پیشنهادی:

```text
Inspect
  ↓
Trim text
  ↓
Standardize values
  ↓
Split City/Country
  ↓
Validate result
```

# 🧩 تمرین عملی

یک جدول مشتری با حداقل ۵۰ رکورد بسازید که شامل موارد زیر باشد:

- ۵ مقدار Age خالی
- ۵ مقدار City خالی
- چند نام شهر با حروف کوچک/بزرگ متفاوت
- چند مقدار با فاصله اضافی
- یک ستون `City-Country`

سپس:

1. سلول‌های خالی را پیدا کنید.
2. تصمیم بگیرید کدام Rowها باید حذف شوند و کدام‌ها باید حفظ شوند.
3. یک مورد متنی ناهماهنگ را با Replace اصلاح کنید.
4. فاصله‌های اضافی را با `TRIM` اصلاح کنید.
5. City-Country را به دو ستون جدا تبدیل کنید.
6. قبل و بعد Dataset را مقایسه کنید.

### Challenge
توضیح دهید چرا حذف همه‌ی Rowهایی که حداقل یک سلول خالی دارند، الزاماً تصمیم درستی نیست.

# 🧠 نکات کلیدی

> **Missing Value یک «مشکل فنی» نیست که همیشه باید حذف شود؛ باید معنی آن را فهمید.**

> **Filter داده را پنهان می‌کند؛ Delete داده را حذف می‌کند.**

> **دو متن که شبیه هم به نظر می‌رسند، الزاماً از نظر داده‌ای یکسان نیستند.**

> **Text to Columns زمانی مفید است که یک Column چند مفهوم مستقل را در خود نگه داشته باشد.**
