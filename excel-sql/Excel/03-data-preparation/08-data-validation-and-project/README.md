# جلسه ۸ — Data Validation و پروژه‌ی یکپارچه فصل

## 🎯 هدف جلسه

تا اینجا یاد گرفتیم داده را وارد کنیم، پاک‌سازی کنیم، مرتب و فیلتر کنیم و چند منبع را به هم متصل یا تجمیع کنیم. حالا یک سؤال مهم باقی می‌ماند:

> **چطور از ورود داده‌ی اشتباه جلوگیری کنیم؟**

این جلسه درباره‌ی **Data Validation** است و در انتها همه‌ی مفاهیم فصل را در یک Workflow یکپارچه تمرین می‌کنیم.

---

# ۱. Data Validation چیست؟

Data Validation یعنی تعیین کنیم یک Cell چه مقدارهایی را می‌تواند قبول کند.

مثلاً اگر ستونی برای `Quantity` داریم، منطقی نیست کاربر بتواند مقدارهایی مثل:

```text
-4
hello
5.8
```

را وارد کند، اگر کسب‌وکار فقط عدد صحیح مثبت می‌خواهد.

Validation کمک می‌کند خطا **قبل از ورود به Dataset** کنترل شود.

---

# ۲. چرا Validation بخشی از Data Quality است؟

Data Cleaning معمولاً بعد از ورود داده انجام می‌شود.

اما اگر بتوانیم از همان ابتدا جلوی بخشی از خطاها را بگیریم، هزینه‌ی اصلاح بسیار کمتر می‌شود.

بنابراین می‌توانیم دو لایه داشته باشیم:

```text
Data Validation
      ↓
Controlled Input
      ↓
Cleaning
      ↓
Analysis
```

> بهترین Data Quality فقط با «پاک کردن خطا» ایجاد نمی‌شود؛ **پیشگیری از خطا** هم اهمیت دارد.

---

# ۳. دسترسی به Data Validation

از برگه‌ی **Data** گزینه‌ی `Data Validation` را انتخاب کنید.

در پنجره‌ی مربوطه، مهم‌ترین بخش `Allow` است؛ این گزینه مشخص می‌کند چه نوع داده‌ای مجاز باشد.

بسته به انتخاب ما، گزینه‌های بیشتری نمایش داده می‌شود.

---

# ۴. Whole Number

اگر یک Cell باید فقط عدد صحیح قبول کند، می‌توانیم `Whole Number` را انتخاب کنیم.

مثلاً برای تعداد محصول:

```text
Data → between
Minimum = 1
Maximum = 500
```

در نتیجه مقدار `25` مجاز است، ولی مقدار `-2` یا `5.5` مجاز نیست.

---

# ۵. Decimal

اگر اعداد اعشاری هم مجاز باشند، `Decimal` انتخاب می‌شود.

مثلاً برای نرخ تخفیف ممکن است بخواهیم مقدار بین صفر و یک باشد:

```text
Minimum = 0
Maximum = 1
```

در این حالت مقدار `0.25` معتبر خواهد بود.

اگر همان سلول را با قالب Percentage نمایش دهیم، این مقدار می‌تواند به شکل `25%` دیده شود.

---

# ۶. List و Dropdown

یکی از کاربردی‌ترین حالت‌ها `List` است.

فرض کنید در ستون `Status` فقط این سه مقدار مجاز باشند:

```text
Pending
Completed
Cancelled
```

به‌جای اینکه کاربر هر بار متن را تایپ کند، می‌توانیم یک Dropdown بسازیم.

این روش احتمال خطاهای تایپی مانند:

```text
Complete
completed
Completed 
```

را کاهش می‌دهد.

---

# ۷. List از محدوده سلولی

لیست می‌تواند از یک Range نیز خوانده شود.

مثلاً در Sheet دیگری فهرست شهرها را داشته باشیم:

```text
Tehran
Shiraz
Tabriz
Mashhad
```

و Validation را به آن Range متصل کنیم.

مزیت این روش این است که به‌جای نوشتن دستی گزینه‌ها داخل Validation، می‌توانیم خود فهرست را مدیریت کنیم.

---

# ۸. Date و Time

می‌توان ورود تاریخ و زمان را نیز محدود کرد.

مثلاً در یک فرم سفارش، تاریخ تحویل نباید قبل از تاریخ سفارش باشد.

یا برای ثبت تاریخ تولد، ممکن است بخواهیم از وارد شدن یک تاریخ آینده جلوگیری کنیم.

Validation می‌تواند بخشی از این کنترل‌ها را پیاده کند.

---

# ۹. Text Length

گاهی مهم است تعداد کاراکترها کنترل شود.

نمونه:

```text
Customer_Code
```

اگر طبق قرارداد سازمانی کد باید دقیقاً ۸ کاراکتر باشد، می‌توانیم طول ورودی را محدود کنیم.

برای شناسه‌هایی که با صفر شروع می‌شوند، توجه به تفاوت **Text و Number** بسیار مهم است.

---

# ۱۰. Custom Validation

اگر شروط آماده نیاز ما را پوشش ندهند، می‌توانیم Formula سفارشی بنویسیم.

برای نمونه، فرض کنید می‌خواهیم عدد موجود در یک Cell حتماً فرد باشد:

```excel
=MOD(A2,2)=1
```

این Formula می‌گوید باقی‌مانده تقسیم مقدار بر ۲ باید برابر ۱ باشد.

> در Custom Validation، Formula باید با توجه به **اولین سلول محدوده‌ی انتخاب‌شده** نوشته شود؛ سپس Excel آن را نسبت به سایر سلول‌ها اعمال می‌کند.

---

# ۱۱. Input Message

در Data Validation می‌توان پیامی تعریف کرد که هنگام انتخاب Cell به کاربر نشان داده شود.

مثلاً برای Quantity:

> تعداد را به‌صورت یک عدد صحیح بین ۱ تا ۵۰۰ وارد کنید.

این کار باعث می‌شود فایل فقط «محدودکننده» نباشد و نقش راهنما هم داشته باشد.

---

# ۱۲. Error Alert

اگر کاربر مقدار نامعتبر وارد کند، می‌توان پیام خطا نمایش داد.

سه حالت مهم:

### Stop
ورودی نامعتبر پذیرفته نمی‌شود.

### Warning
به کاربر هشدار داده می‌شود و در برخی سناریوها امکان ادامه وجود دارد.

### Information
صرفاً پیام اطلاع‌رسانی نمایش داده می‌شود.

برای داده‌های حیاتی، `Stop` معمولاً انتخاب سخت‌گیرانه‌تری است.

---

# ۱۳. Circle Invalid Data

گاهی نمی‌خواهیم بلافاصله داده را حذف یا ویرایش کنیم؛ فقط می‌خواهیم مقدارهای نامعتبر را پیدا کنیم.

گزینه‌ی `Circle Invalid Data` برای همین منظور مفید است و Cellهای دارای مقدار نامعتبر را مشخص می‌کند.

این قابلیت برای Audit اولیه‌ی فایل بسیار کاربردی است.

---

# ۱۴. پروژه‌ی یکپارچه فصل

حالا همه‌ی ابزارهای فصل را کنار هم قرار می‌دهیم.

فرض کنید یک فروشگاه سه منبع دارد:

```text
sales_jan.csv
sales_feb.csv
products.xlsx
```

و یک فایل داخلی برای اطلاعات مشتریان دارد.

### مرحله ۱ — Import
فایل‌ها را با Get Data وارد کنید.

### مرحله ۲ — Inspect
نوع داده، Header، نام ستون‌ها و مقدارهای مشکوک را بررسی کنید.

### مرحله ۳ — Transform
در Power Query:

- ستون‌های اضافی را حذف کنید؛
- نام ستون‌ها را استاندارد کنید؛
- فاصله‌های اضافی را پاک کنید؛
- نوع داده را اصلاح کنید؛
- در صورت نیاز Split و Replace انجام دهید.

### مرحله ۴ — Append
فایل‌های January و February را ترکیب کنید.

### مرحله ۵ — Merge
اطلاعات Product و Customer را با Key مناسب به Dataset فروش اضافه کنید.

### مرحله ۶ — Quality Check
Duplicate، Missing Value و Matchهای ناقص را بررسی کنید.

### مرحله ۷ — Filter / Sort
مثلاً فروش‌های Completed را جدا کنید و بر اساس Amount مرتب کنید.

### مرحله ۸ — Load
Dataset نهایی را وارد Worksheet کنید.

### مرحله ۹ — Validation
در یک Sheet مخصوص ورود سفارش، Validationهای مناسب برای Status، Quantity، Date و سایر فیلدها قرار دهید.

---

# ۱۵. خروجی نهایی پروژه

در پایان باید حداقل این ساختار را داشته باشید:

```text
Workbook
│
├── Raw / Source
├── Clean_Sales
├── Products
├── Customers
├── Data_Entry
└── Summary
```

در `Clean_Sales` داده‌ی آماده‌ی تحلیل قرار می‌گیرد.

در `Data_Entry` ورودی جدید با Validation کنترل می‌شود.

در فصل‌های بعد، از `Clean_Sales` برای Formula، Pivot، Chart و Dashboard استفاده خواهیم کرد.

---

# 🧩 تمرین نهایی فصل

یک سناریوی فروش طراحی کنید و حداقل ۵۰۰ رکورد تولید کنید.

Dataset باید عمداً این مشکلات را داشته باشد:

- Duplicate
- Missing Value
- فاصله اضافی
- چند شکل مختلف برای یک مقدار متنی
- تاریخ نامعتبر یا ناسازگار
- حداقل دو Source مجزا

سپس Workflow زیر را اجرا کنید:

```text
Import
→ Transform
→ Clean
→ Append / Merge
→ Validate
→ Filter / Sort
→ Final Dataset
```

### خروجی مورد انتظار

در پایان باید بتوانید به این سؤال پاسخ دهید:

> «اگر فردا یک فایل جدید با همین ساختار دریافت کنیم، آیا می‌توانم همین فرآیند را دوباره اجرا کنم؟»

اگر پاسخ شما «بله» است، یعنی از یک عملیات دستی ساده فاصله گرفته‌اید و به سمت یک Workflow قابل تکرار حرکت کرده‌اید.

---

# 🧠 جمع‌بندی فصل

در این فصل دیدیم که آماده‌سازی داده فقط مرتب کردن چند سلول نیست.

یک Workflow درست می‌تواند از این اجزا تشکیل شود:

```text
Source
  ↓
Import
  ↓
Transform
  ↓
Clean
  ↓
Combine
  ↓
Validate
  ↓
Analysis-ready Data
```

مهم‌ترین مفاهیمی که باید به خاطر داشته باشید:

- `Get Data` برای دریافت داده از منابع مختلف کاربرد دارد.
- `Connection` و `Query` می‌توانند فرایند دریافت داده را تکرارپذیرتر کنند.
- `Power Query` یک محیط مهم برای Transform داده است.
- Duplicate باید بر اساس تعریف درست رکورد شناسایی شود.
- Missing Value همیشه به معنی «حذف Row» نیست.
- Filter داده را پنهان می‌کند؛ Delete آن را حذف می‌کند.
- `Sort` و `Filter` ابزارهای ساده اما قدرتمند برای بررسی Dataset هستند.
- `Append` برای روی‌هم‌گذاشتن Datasetهای مشابه است.
- `Merge` برای وصل کردن Datasetها بر اساس Key است.
- `Consolidate` برای ساخت خروجی‌های تجمیعی از چند محدوده کاربرد دارد.
- `Data Validation` بخشی از کنترل کیفیت داده پیش از ورود است.

---

## 🔜 در فصل بعد چه خواهیم کرد؟

حالا یک Dataset تمیز در اختیار داریم. مرحله‌ی بعد این است که بتوانیم از دل آن **اطلاعات جدید استخراج کنیم**.

در فصل بعد وارد Lookupها، توابع شرطی و منطقی، توابع متنی، ساختار Tableها و فرمول‌های پیشرفته‌تر می‌شویم.
