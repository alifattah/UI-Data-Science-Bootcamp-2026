# جلسه ۲ — اتصال به منابع و Power Query

## 🎯 هدف جلسه

در این جلسه با مفهوم **Connection** و محیط **Power Query Editor** آشنا می‌شویم. هدف این است که بفهمیم Excel چگونه می‌تواند با یک منبع خارجی ارتباط داشته باشد و پیش از ورود نهایی داده، چه تغییراتی روی آن انجام دهیم.

---

# ۱. وقتی داده در Excel نیست چه می‌کنیم؟

تا اینجا فرض کردیم داده داخل یک فایل Excel یا CSV قرار دارد. اما در شرکت‌ها داده ممکن است در منابعی مثل:

- Database
- فایل Access
- فایل‌های متنی
- چندین Workbook
- سرویس‌های آنلاین

ذخیره شده باشد.

Excel لازم نیست همیشه محل اصلی نگهداری داده باشد. می‌توانیم داده را از منبع اصلی دریافت کنیم، روی آن آماده‌سازی انجام دهیم و سپس نتیجه را وارد Worksheet کنیم.

```text
Data Source
    ↓
Connection / Query
    ↓
Transform
    ↓
Load
    ↓
Excel Worksheet
```

---

# ۲. Database و Excel چه رابطه‌ای دارند؟

Database معمولاً برای نگهداری ساخت‌یافته‌ی داده و کار با حجم و تعداد تراکنش‌های بیشتر مناسب است. Excel در سمت تحلیل تعاملی، محاسبات و گزارش‌سازی سریع بسیار کاربردی است.

بنابراین یک سناریوی واقعی می‌تواند این باشد:

> فروشگاه داده سفارش‌های خود را در Database نگهداری می‌کند و تحلیلگر، بخشی از داده موردنیاز را برای گزارش‌سازی وارد Excel می‌کند.

در این بوت‌کمپ بعداً با Database و SQL مفصل‌تر کار خواهیم کرد؛ فعلاً مهم است که مفهوم اتصال بین ابزارها را درک کنیم.

---

# ۳. From Database

در Excel می‌توان از مسیر `Data → Get Data → From Database` به منابعی مانند Databaseهای رایج یا Access متصل شد.

نحوه اتصال بسته به منبع فرق دارد، اما منطق یکسان است:

1. منبع را مشخص می‌کنیم.
2. منبع یا Table موردنظر را انتخاب می‌کنیم.
3. Preview را بررسی می‌کنیم.
4. در صورت نیاز Transform انجام می‌دهیم.
5. داده را Load می‌کنیم.

### مثال

فرض کنید Database شرکت سه جدول دارد:

```text
Customers
Orders
Products
```

اگر فقط برای گزارش فروش نیاز به `Orders` داشته باشیم، لازم نیست همه دیتابیس را وارد Workbook کنیم. بهتر است فقط داده موردنیاز را دریافت کنیم.

> این طرز فکر مهم است: **همیشه کل داده را نیاوریم؛ داده‌ی موردنیاز مسئله را دریافت کنیم.**

---

# ۴. Connection یعنی چه؟

وقتی از یک منبع خارجی داده می‌گیریم، Excel می‌تواند اطلاعات مربوط به منبع و Query را حفظ کند.

در نتیجه بین Workbook و Source یک مسیر مشخص وجود دارد.

مثلاً:

```text
sales.csv
   ↓
Sales Query
   ↓
Sales Sheet
```

اگر فایل منبع تغییر کند، Query را می‌توان Refresh کرد و داده را دوباره دریافت کرد.

## Refresh

فرض کنید هر روز فایل `sales.csv` با سفارش‌های جدید جایگزین می‌شود. اگر Query ما همچنان به همان مسیر و ساختار منبع متصل باشد، می‌توانیم به‌جای ساختن فرایند از صفر، آن را Refresh کنیم.

> **Refresh یعنی اجرای دوباره مسیر دریافت و آماده‌سازی داده بر اساس منبع فعلی.**

---

# ۵. اگر داده را از Sheet پاک کنیم چه می‌شود؟

یک نکته مهم این است که داده‌ی Load شده با خود Query یکی نیست.

ممکن است داده‌ای را از Worksheet پاک کنید، اما Query هنوز وجود داشته باشد. در چنین وضعیتی می‌توانیم Query را دوباره Load یا Refresh کنیم.

در مقابل، اگر خود Connection یا Query را حذف کنیم، دیگر مسیر قبلی برای Refresh در دسترس نخواهد بود.

این تفکیک را به خاطر بسپارید:

```text
Source ≠ Query ≠ Loaded Table
```

این سه مفهوم در کار با Power Query بسیار مهم هستند.

---

# ۶. Transform Data و Power Query Editor

وقتی به جای `Load` روی `Transform Data` کلیک می‌کنیم، وارد **Power Query Editor** می‌شویم.

Power Query را بهتر است یک لایه‌ی آماده‌سازی بین منبع داده و Excel بدانیم.

مثلاً:

```text
Raw CSV
   ↓
Power Query
   ├── حذف ستون اضافی
   ├── اصلاح نوع تاریخ
   ├── Trim متن
   ├── Filter
   ├── Split Column
   └── Merge
   ↓
Clean Data
```

این یعنی لازم نیست همه‌ی تغییرات را مستقیماً روی Worksheet انجام دهیم.

---

# ۷. پنجره Power Query Editor

در محیط Power Query بخش‌هایی برای مشاهده داده، اعمال Transform و مدیریت مراحل وجود دارد.

یکی از ایده‌های مهم این محیط، **Step** است. هر تغییری که انجام می‌دهیم به‌عنوان یک مرحله در Query ثبت می‌شود.

مثلاً:

```text
Source
→ Promoted Headers
→ Changed Type
→ Removed Columns
→ Filtered Rows
→ Split Column
```

مزیت این رویکرد این است که فرآیند آماده‌سازی داده، قابل مشاهده و تا حد زیادی قابل تکرار می‌شود.

---

# ۸. Manage Columns و Reduce Rows

در Power Query می‌توانیم ستون‌ها و ردیف‌های اضافی را مدیریت کنیم.

### Manage Columns

کارهایی مانند:

- Remove Columns
- Choose Columns
- Rename Columns

### Reduce Rows

کارهایی مثل:

- حذف چند ردیف اول
- حذف ردیف‌های خالی
- فیلتر کردن ردیف‌ها
- نگه داشتن تعداد مشخصی از ردیف‌ها

برای مثال اگر فایل CSV سه ردیف توضیح در ابتدای فایل داشته باشد، می‌توانیم ابتدا آن ردیف‌ها را حذف کنیم و سپس Header اصلی را تنظیم کنیم.

---

# ۹. Transform Columns

در Power Query ابزارهای مختلفی برای تغییر محتوای ستون وجود دارد.

مثلاً می‌توانیم:

- نوع داده را تغییر دهیم.
- متن را Upper/Lower کنیم.
- فضای خالی را پاک کنیم.
- بخش‌های متن را Replace کنیم.
- یک ستون را Split کنیم.
- مقدارها را استاندارد کنیم.

### مثال Split Column

فرض کنید ستون زیر را داریم:

```text
Tehran - Iran
Shiraz - Iran
Tabriz - Iran
```

می‌خواهیم آن را به دو ستون تبدیل کنیم:

| City | Country |
|---|---|
| Tehran | Iran |
| Shiraz | Iran |
| Tabriz | Iran |

می‌توانیم `Split Column → By Delimiter` را انتخاب و `-` را جداکننده قرار دهیم.

---

# ۱۰. Replace Values

یکی از عملیات‌های بسیار رایج در Data Cleaning، جایگزینی مقدار است.

فرض کنید در ستون شهر این موارد را داریم:

```text
Tehran
tehran
TEHRAN
```

در تحلیل شاید بخواهیم این مقادیر یکسان دیده شوند.

در Power Query می‌توان با `Replace Values` یک مقدار را با مقدار استاندارد جایگزین کرد.

> البته قبل از یکسان‌سازی باید مطمئن شویم این تفاوت واقعاً یک خطای ثبت داده است و معنی متفاوتی ندارد.

---

# ۱۱. Close & Load

وقتی آماده‌سازی داده تمام شد، با گزینه‌های `Close & Load` یا `Close & Load To` نتیجه را به Excel برمی‌گردانیم.

در این مرحله باید به یک تفاوت مهم توجه کنیم:

**آنچه در Worksheet می‌بینیم، خروجی Transform شده است؛ منبع اصلی همچنان منبع داده‌ی Query است.**

به همین دلیل در آینده می‌توانیم مسیر را دوباره اجرا کنیم.

---

# ۱۲. یک مثال کامل

فرض کنید یک فایل فروش داریم:

```text
order_id;customer;city;amount
1001; Ali ;tehran;5400000
1002;Sara;Tehran;3200000
1003;Ali;TEHRAN;1800000
```

مشکل‌ها:

- `Ali` فاصله اضافی دارد.
- شکل نوشتاری `tehran` یکسان نیست.
- داده با `;` جدا شده است.

یک Workflow منطقی:

```text
Import CSV
   ↓
Check Delimiter
   ↓
Transform Data
   ↓
Trim Customer
   ↓
Standardize City
   ↓
Check Data Types
   ↓
Close & Load
```

این دقیقاً همان نوع فرآیندی است که در پروژه‌های واقعی بارها تکرار می‌شود.

---

# 🧩 تمرین عملی

یک CSV با حداقل ۵۰ ردیف فروش تهیه کنید که عمداً چند مشکل داشته باشد:

- فاصله اضافی در نام مشتری
- سه شکل مختلف برای نام یک شهر
- یک ستون اضافی که لازم نیست
- چند مقدار متنی در ستونی که باید عددی باشد
- چند ردیف خالی

سپس:

1. فایل را Import کنید.
2. وارد Power Query Editor شوید.
3. ستون اضافی را حذف کنید.
4. متن‌ها را استاندارد کنید.
5. نوع داده مبلغ را اصلاح کنید.
6. ردیف‌های خالی را حذف یا فیلتر کنید.
7. Query را با نام مناسب ذخیره کنید.
8. داده را Load کنید.
9. یکی از مقادیر منبع را تغییر دهید و Refresh را امتحان کنید.

---

# 🧠 نکات کلیدی

> **Power Query را می‌توان لایه‌ی آماده‌سازی داده بین Source و Excel دانست.**

> **Connection مسیر ارتباط با منبع را حفظ می‌کند.**

> **Transform Data اجازه می‌دهد قبل از Load، داده را آماده کنیم.**

> **Stepها باعث می‌شوند فرآیند Transform قابل مشاهده و تکرارپذیرتر شود.**

> **Source، Query و خروجی Load شده مفاهیم متفاوتی هستند.**
