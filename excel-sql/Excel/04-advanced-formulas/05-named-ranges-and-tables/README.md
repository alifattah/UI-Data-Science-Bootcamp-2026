# جلسه ۵ — Named Range و Excel Table

## چرا باید محدوده‌ها را نام‌گذاری کنیم؟

در فایل‌های کوچک، نوشتن `B2:B20` مشکلی ایجاد نمی‌کند. اما وقتی Workbook بزرگ می‌شود، فرمول‌هایی مثل:

```excel
=SUM(Sales!B2:B5000)
```

خیلی زود خوانایی خود را از دست می‌دهند.

در Excel می‌توانیم به یک محدوده نام بدهیم و بعد در فرمول‌ها به جای آدرس خام از نام آن استفاده کنیم.

---

## 1. Named Range چیست؟

فرض کنید محدوده `B2:B100` شامل مبلغ فروش است. می‌توانیم نام آن را `SalesAmount` بگذاریم و بنویسیم:

```excel
=SUM(SalesAmount)
```

فرمول حالا تقریباً بدون نیاز به نگاه کردن به فایل، معنی خودش را توضیح می‌دهد.

---

## 2. ساخت Named Range

یک محدوده را انتخاب کنید و از مسیر زیر استفاده کنید:

```text
Formulas → Defined Names → Define Name
```

برای نام بهتر است از نام‌های توصیفی استفاده کنید:

```text
SalesAmount
TaxRate
CustomerIDs
ProductPrices
```

از نام‌هایی که ممکن است با Cell Reference اشتباه گرفته شوند یا دارای فاصله باشند استفاده نکنید.

---

## 3. Create from Selection

اگر جدول شما Header دارد، می‌توان از:

```text
Formulas → Create from Selection
```

استفاده کرد.

Excel می‌تواند بر اساس عنوان‌های موجود در سطر یا ستون، Named Range تولید کند.

این روش برای داده‌هایی که ساختار مرتب دارند بسیار سریع‌تر است.

---

## 4. Name Manager

از مسیر:

```text
Formulas → Name Manager
```

می‌توانیم تمام Named Rangeهای Workbook را ببینیم، تغییر دهیم یا حذف کنیم.

مثلاً اگر `SalesAmount` دیگر نباید `B2:B100` باشد، می‌توان Reference آن را اصلاح کرد.

---

# 5. Excel Table چیست؟

`Table` را نباید فقط یک «جدول خوشگل» بدانیم.

Excel Table یک ساختار داده‌ی مشخص است که امکاناتی مانند:

- Header
- Filter
- توسعه خودکار محدوده
- Structured References
- قالب‌بندی یکپارچه
- ردیف جمع
- محاسبات خودکار

را در اختیارمان قرار می‌دهد.

---

## 6. ساخت Table

محدوده داده را انتخاب کنید و یکی از این مسیرها را بروید:

```text
Insert → Table
```

یا:

```text
Home → Format as Table
```

اگر داده شما Header دارد، گزینه `My table has headers` را بررسی کنید.

---

## 7. چرا Table برای تحلیل داده بهتر است؟

یکی از مزایای مهم Table این است که وقتی یک Row جدید به انتهای جدول اضافه می‌کنیم، ساختار جدول می‌تواند خودکار گسترش پیدا کند.

این ویژگی در گزارش‌هایی که دائماً رکورد جدید دریافت می‌کنند بسیار مهم است.

مثلاً اگر جدول سفارشات شما ۱۰۰۰ رکورد داشته باشد و فردا ۵۰ سفارش جدید اضافه شود، Table می‌تواند این رکوردها را به ساختار موجود اضافه کند و در بسیاری از فرمول‌ها و گزارش‌ها نیازی به اصلاح دستی محدوده نخواهد بود.

---

## 8. Structured References

به جای:

```excel
=SUM(C2:C500)
```

اگر Table ما `Orders` و ستون فروش `SalesAmount` باشد، می‌توانیم از چیزی شبیه این استفاده کنیم:

```excel
=SUM(Orders[SalesAmount])
```

این فرمول خواناتر است و با رشد Table نیز بهتر مقیاس می‌گیرد.

---

## 9. Table Design

وقتی داخل Table قرار داریم، برگه `Table Design` در دسترس قرار می‌گیرد.

از این قسمت می‌توان:

- نام Table را تعیین کرد.
- Total Row را فعال کرد.
- Filter Button را مدیریت کرد.
- قالب جدول را تغییر داد.
- داده‌های Duplicate را حذف کرد.
- Table را دوباره به Range تبدیل کرد.

---

## 10. Total Row

با فعال کردن Total Row می‌توان محاسباتی مثل Sum، Average، Count و ... را مستقیماً در انتهای جدول نمایش داد.

این روش برای گزارش‌های سریع بسیار کاربردی است، اما برای مدل‌های تحلیلی بزرگ بهتر است منطق محاسبات را جدا و شفاف نگه داریم.

---

## 11. Named Range یا Table؟

هر کدام برای مسئله‌ای مناسب‌ترند.

| نیاز | انتخاب مناسب |
|---|---|
| یک محدوده مشخص و مستقل | Named Range |
| جدول رکوردها با Header و Filter | Excel Table |
| پارامتر ثابت مثل Tax Rate | Named Range |
| دیتاستی که مرتب بزرگ می‌شود | Table |
| فرمول‌های طولانی و خوانایی بیشتر | هر دو، بسته به ساختار |

---

## 🧪 تمرین

یک جدول `Orders` با ستون‌های زیر بسازید:

`Order ID | Customer | Product | Quantity | Unit Price`

سپس:

1. آن را به Excel Table تبدیل کنید.
2. نام Table را `Orders` بگذارید.
3. یک ستون `Total Price` بسازید.
4. قیمت کل را با Structured Reference محاسبه کنید.
5. یک Named Range برای نرخ مالیات بسازید.
6. محاسبه قیمت نهایی را طوری بنویسید که از نام نرخ مالیات استفاده کند.

---

## ✅ خلاصه

- Named Range خوانایی فرمول‌ها را بیشتر می‌کند.
- Name Manager محل مدیریت نام‌هاست.
- Excel Table یک ساختار داده‌ی واقعی‌تر از یک Range ساده است.
- Structured Reference فرمول‌ها را خواناتر و قابل توسعه‌تر می‌کند.
- برای مدل‌سازی حرفه‌ای باید تفاوت «ظاهر جدول» با «ساختار داده» را بدانیم.
