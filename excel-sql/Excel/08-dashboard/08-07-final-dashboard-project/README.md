# جلسه ۸-۷ — پروژه پایانی Dashboard

## هدف پروژه

در این پروژه قرار است تمام مهارت‌های فصل‌های قبل را کنار هم قرار دهیم و یک Dashboard فروش قابل ارائه بسازیم.

## سناریو

فرض کنید مدیر یک فروشگاه زنجیره‌ای هستیم و داده‌های یک سال فروش را در اختیار داریم. هر رکورد شامل اطلاعاتی مانند تاریخ، شعبه، منطقه، محصول، تعداد و مبلغ فروش است.

مدیر می‌خواهد در یک صفحه بتواند به این سؤال‌ها پاسخ دهد:

- فروش کل چقدر است؟
- نسبت به دوره قبل چه تغییری کرده؟
- کدام منطقه بیشترین فروش را داشته؟
- کدام محصولات پرفروش‌ترند؟
- فروش در طول زمان چه روندی دارد؟
- با انتخاب یک منطقه یا دوره چه تغییری در نتایج ایجاد می‌شود؟

## خروجی مورد انتظار

Dashboard باید حداقل این اجزا را داشته باشد:

### KPIها

- Total Revenue
- Total Orders
- Average Order Value
- Growth / Target Achievement

### نمودارها

- Monthly Revenue — Line Chart
- Revenue by Region — Column/Bar Chart
- Top Products — Bar Chart
- در صورت نیاز یک نمودار تکمیلی برای Mix یا Performance

### کنترل‌های تعاملی

- Slicer برای Region
- Slicer برای Product Category
- Timeline برای Date

### ساختار داده

داده خام باید به شکل یک Table منظم باشد و پیش از ساخت Dashboard، کیفیت آن بررسی شود.

## مراحل پروژه

```text
01. دریافت داده
        ↓
02. Cleaning
        ↓
03. ساخت Calculated Columns در صورت نیاز
        ↓
04. تبدیل به Table
        ↓
05. ساخت PivotTableها
        ↓
06. ساخت PivotChartها
        ↓
07. ساخت KPIها
        ↓
08. اضافه کردن Slicer/Timeline
        ↓
09. طراحی Layout
        ↓
10. کنترل کیفیت
```

## مرحله ۱ — آماده‌سازی

قبل از ساخت گزارش، موارد زیر را بررسی کنید:

- Headerها واضح باشند.
- داده تکراری غیرمجاز وجود نداشته باشد.
- تاریخ‌ها نوع صحیح داشته باشند.
- مبلغ و تعداد عدد باشند.
- مقادیر خالی مهم مشخص شده باشند.
- نام دسته‌ها استاندارد باشند.

## مرحله ۲ — ساخت Pivotها

حداقل سه Pivot بسازید:

1. فروش ماهانه
2. فروش منطقه‌ای
3. فروش محصولی

برای KPIها نیز می‌توانید Pivot یا Formulaهای وابسته به Pivot بسازید.

## مرحله ۳ — طراحی صفحه

یک Worksheet با نام `Dashboard` بسازید و آن را برای ارائه اختصاص دهید.

پیشنهاد Layout:

```text
┌─────────────────────────────────────────────┐
│                SALES DASHBOARD              │
│  [Region] [Category] [Date Timeline]        │
├──────────┬──────────┬──────────┬────────────┤
│ Revenue  │ Orders   │ Avg Ord. │ Growth     │
├───────────────────────┬─────────────────────┤
│ Monthly Revenue       │ Revenue by Region   │
│       LINE            │       BAR           │
├───────────────────────┼─────────────────────┤
│ Top Products          │ Detail / Notes      │
└───────────────────────┴─────────────────────┘
```

## مرحله ۴ — تعامل

Slicerها باید تا حد ممکن چند جزء مرتبط را کنترل کنند. بررسی کنید که انتخاب Region واقعاً روی تمام گزارش‌های مرتبط اعمال شود.

## مرحله ۵ — کنترل کیفیت

قبل از تحویل Dashboard:

- Total Revenue را با داده خام تطبیق دهید.
- چند فیلتر تصادفی اعمال کنید و نتیجه را کنترل کنید.
- یک KPI را با فرمول مستقل بررسی کنید.
- مطمئن شوید عنوان‌ها پس از فیلتر همچنان معنا دارند.
- نمودارها محور و واحد قابل فهم داشته باشند.
- داشبورد بدون توضیح طولانی قابل فهم باشد.

## معیار ارزیابی

| بخش | انتظار |
|---|---|
| Data Quality | داده تمیز و ساختاریافته |
| Analysis | KPIها و Pivotهای درست |
| Visualization | انتخاب نمودار مناسب |
| Interactivity | فیلترهای کاربردی |
| Design | Layout منظم و خوانا |
| Accuracy | تطبیق نتایج با منبع |
| Storytelling | انتقال واضح یک پیام تحلیلی |

## Challenge نهایی

فرض کنید مدیر در جلسه فقط ۳۰ ثانیه فرصت دارد Dashboard را ببیند.

آیا می‌تواند در همین ۳۰ ثانیه بفهمد:

1. وضعیت فعلی فروش چگونه است؟
2. روند چه تغییری کرده است؟
3. بهترین/ضعیف‌ترین منطقه کدام است؟
4. با چه فیلتری داده را دقیق‌تر بررسی کند؟

اگر پاسخ «نه» است، قبل از اضافه کردن قابلیت جدید، طراحی داشبورد را اصلاح کنید.
