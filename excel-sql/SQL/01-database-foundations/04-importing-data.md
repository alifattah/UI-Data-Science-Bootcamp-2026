# درس ۴ — وارد کردن داده به MySQL

در پروژه تحلیل داده، داده‌ها ممکن است از فایل‌های CSV، خروجی سامانه‌های عملیاتی یا فایل‌های SQL دریافت شوند. در این درس یاد می‌گیریم چگونه این داده‌ها را وارد MySQL کنیم و بعد از Import، صحت بارگذاری را بررسی کنیم.

## ۱. دو نوع فایل رایج

برای تمرین این درس، یک فایل نمونه در ریپو قرار داده‌ایم: [customers_sample.csv](../practice/customers_sample.csv).

### CSV

فایل CSV داده جدولی را به شکل متن نگه می‌دارد. سطر اول معمولاً نام ستون‌هاست و مقادیر هر سطر با جداکننده‌ای مانند کاما از هم جدا می‌شوند.

نمونه فایل `customers.csv`:

```csv
customer_id,full_name,email,city
1,Niloofar Ahmadi,niloofar@example.com,Isfahan
2,Arman Rezaei,arman@example.com,Shiraz
3,Sara Mohammadi,sara@example.com,Tehran
```

### SQL Dump

فایل SQL معمولاً مجموعه‌ای از دستورهای SQL است؛ ممکن است شامل `CREATE TABLE`، `INSERT` و دستورهای دیگری برای بازسازی ساختار و داده باشد.

## ۲. روش اول: بارگذاری CSV با LOAD DATA LOCAL INFILE

ابتدا جدول مقصد را می‌سازیم:

```sql
CREATE TABLE customers_import (
    customer_id INT,
    full_name VARCHAR(120),
    email VARCHAR(160),
    city VARCHAR(80)
);
```

سپس فایل را بارگذاری می‌کنیم:

```sql
LOAD DATA LOCAL INFILE '/path/to/customers.csv'
INTO TABLE customers_import
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(customer_id, full_name, email, city);
```

بخش‌های مهم دستور:

| بخش | کاربرد |
|---|---|
| `LOCAL INFILE` | فایل از سمت Client خوانده می‌شود |
| `INTO TABLE` | جدول مقصد |
| `FIELDS TERMINATED BY` | جداکننده ستون‌ها |
| `OPTIONALLY ENCLOSED BY` | پشتیبانی از متن محصور در کوتیشن |
| `LINES TERMINATED BY` | جداکننده سطرها |
| `IGNORE 1 LINES` | رد کردن ردیف عنوان ستون‌ها |

مسیر فایل باید با سیستم‌عامل و محیط اجرای Client سازگار باشد. در بعضی تنظیمات امنیتی MySQL یا ابزار اتصال، قابلیت `LOCAL INFILE` غیرفعال است و باید با سیاست امنیتی محیط هماهنگ شود؛ آن را بدون بررسی روی سرور عمومی فعال نکنید.

> نکته: اگر فایل شما با فرمت دیگری ذخیره شده، مثلاً جداکننده آن نقطه‌ویرگول است، مقدار `FIELDS TERMINATED BY` را متناسب با فایل تغییر دهید. همچنین برای فایل‌های دارای نقل‌قول، جداکننده و Escape را با ساختار واقعی فایل هماهنگ کنید.

## ۳. روش دوم: Import از محیط گرافیکی

در ابزارهایی مانند DataGrip یا MySQL Workbench معمولاً می‌توانید:

1. جدول مقصد را انتخاب کنید یا ابتدا آن را بسازید.
2. گزینه Import Data را اجرا کنید.
3. فایل CSV را معرفی کنید.
4. جداکننده و وجود Header را بررسی کنید.
5. نگاشت ستون‌های فایل به ستون‌های جدول را کنترل کنید.
6. عملیات Import را اجرا کنید.

نام دقیق گزینه‌ها به نسخه ابزار وابسته است.

## ۴. وارد کردن فایل SQL

اگر فایل ورودی شامل دستورهای SQL است، می‌توان آن را از ترمینال اجرا کرد:

```bash
mysql -u your_user -p database_name < backup.sql
```

در این مثال:
- `your_user` نام کاربری MySQL است.
- `database_name` دیتابیس مقصد است.
- `backup.sql` مسیر فایل SQL است.

اگر فایل خودش دیتابیس را انتخاب یا ایجاد می‌کند، ممکن است لازم باشد نام دیتابیس را از دستور خط فرمان حذف کنید؛ قبل از اجرا محتوای فایل را بررسی کنید.

## ۵. کنترل کیفیت پس از Import

موفق بودن عملیات Import به معنی صحیح بودن داده نیست. حداقل این بررسی‌ها را انجام دهید:

```sql
-- تعداد ردیف‌های واردشده
SELECT COUNT(*) AS row_count
FROM customers_import;

-- مشاهده چند ردیف نمونه
SELECT *
FROM customers_import
LIMIT 10;

-- بررسی مقدارهای خالی در ستون کلیدی
SELECT COUNT(*) AS missing_email
FROM customers_import
WHERE email IS NULL OR email = '';
```

همچنین موارد زیر را بررسی کنید:
- آیا تعداد سطرها با فایل مبدا سازگار است؟
- آیا متن فارسی یا کاراکترهای خاص درست نمایش داده می‌شوند؟
- آیا تاریخ‌ها و اعداد با نوع داده مقصد سازگارند؟
- آیا مقادیر تکراری یا غیرمنتظره وجود دارند؟
- آیا ترتیب ستون‌های فایل با نگاشت مقصد درست تطبیق داده شده است؟

## سناریوی عملی

فایل CSV فروش را دریافت کرده‌اید که ستون‌های زیر را دارد:

`order_id,customer_id,order_date,status,total_amount`

یک جدول مقصد بسازید، فایل را Import کنید و با Queryهای مناسب:
1. تعداد سفارش‌ها را بشمارید.
2. پنج ردیف اول را ببینید.
3. سفارش‌هایی را که مبلغ ندارند پیدا کنید.
4. وضعیت‌های منحصربه‌فرد را استخراج کنید.

## نکات کلیدی

- CSV فقط داده متنی جدولی است؛ فایل SQL می‌تواند ساختار و داده را همزمان ایجاد کند.
- قبل از Import، Schema مقصد و نوع ستون‌ها را مشخص کنید.
- از `LOCAL INFILE` فقط در محیطی استفاده کنید که مجوز و تنظیمات آن بررسی شده باشد.
- همیشه بعد از بارگذاری، تعداد و نمونه داده‌ها را کنترل کنید.
