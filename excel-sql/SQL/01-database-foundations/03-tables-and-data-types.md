# درس ۳ — طراحی جدول و انتخاب نوع داده در MySQL

## چرا نوع داده مهم است؟

هنگام ساخت جدول باید برای هر ستون مشخص کنیم چه نوع مقداری در آن قرار می‌گیرد. انتخاب درست نوع داده باعث می‌شود داده‌ها معتبرتر ذخیره شوند، محاسبات قابل اعتماد باشند و فضای ذخیره‌سازی بی‌دلیل مصرف نشود.

برای مثال، مبلغ سفارش باید عددی باشد؛ اما شماره تماس یا کد پستی، با وجود ظاهر عددی، معمولاً ماهیت متنی دارد. ممکن است با صفر شروع شود و قرار نیست روی آن جمع و تفریق انجام دهیم.

## ۱. ساختار دستور CREATE TABLE

```sql
CREATE TABLE table_name (
    column_name data_type constraints,
    another_column another_type,
    table_constraints
);
```

هر ستون حداقل یک نام و نوع داده دارد. Constraintها نیز قواعدی هستند که مقدارهای مجاز را محدود می‌کنند.

## ۲. نوع داده‌های متداول

### متن

| نوع | کاربرد |
|---|---|
| `CHAR(n)` | متن با طول ثابت و کوتاه، مانند کدهای ثابت |
| `VARCHAR(n)` | متن با طول متغیر و سقف مشخص، مانند نام و ایمیل |
| `TEXT` | متن‌های بلند، مانند توضیحات محصول |

مثال:

```sql
CREATE TABLE categories (
    category_id INT,
    category_name VARCHAR(80) NOT NULL,
    description TEXT
);
```

در انتخاب `VARCHAR(n)` باید به طول مورد انتظار و محدودیت‌های ردیف توجه کرد. `TEXT` نیز به معنی ظرفیت نامحدود نیست؛ خانواده TEXT سقف‌های مشخصی دارد.

### عدد صحیح

| نوع | کاربرد معمول |
|---|---|
| `TINYINT` | عددهای صحیح کوچک |
| `SMALLINT` | عددهای صحیح کوچک تا متوسط |
| `INT` | شمارنده‌ها و شناسه‌های معمول |
| `BIGINT` | شناسه‌ها یا شمارنده‌های با دامنه بزرگ |

ویژگی `UNSIGNED` دامنه را به صفر و اعداد مثبت محدود می‌کند؛ برای مثال:

```sql
quantity INT UNSIGNED
```

از آن برای تعداد کالا استفاده می‌کنیم، چون تعداد منفی معنا ندارد.

> نکته: در نسخه‌های جدید MySQL عددی مانند `INT(11)` دامنه عدد را بزرگ‌تر نمی‌کند. عرض نمایشی عدد در نسخه‌های جدید منسوخ شده است؛ در طراحی معمول کافی است `INT` یا `BIGINT` بنویسید.

### عدد اعشاری و مبلغ

`DECIMAL(p,s)` برای مقادیر دقیق با تعداد رقم اعشار مشخص مناسب است.

- `p`: تعداد کل رقم‌ها
- `s`: تعداد رقم‌های بعد از ممیز

برای قیمت و مبلغ معمولاً `DECIMAL` را به `FLOAT` یا `DOUBLE` ترجیح می‌دهیم؛ زیرا انواع شناور تقریبی‌اند.

```sql
price DECIMAL(12,2) NOT NULL
```

### تاریخ و زمان

| نوع | کاربرد |
|---|---|
| `DATE` | تاریخ بدون ساعت |
| `TIME` | ساعت یا بازه زمانی |
| `DATETIME` | تاریخ و ساعت |
| `TIMESTAMP` | زمان ثبت‌شده با تبدیل وابسته به Time Zone نشست |

برای زمان ایجاد سفارش معمولاً می‌توان از `DATETIME` یا `TIMESTAMP` استفاده کرد؛ انتخاب به نیاز سامانه و سیاست Time Zone بستگی دارد.

```sql
order_date DATETIME NOT NULL,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

**تفاوت مهم:** مقدار `TIMESTAMP` در MySQL هنگام ذخیره و بازیابی با Time Zone نشست تبدیل می‌شود؛ `DATETIME` چنین تبدیل خودکاری ندارد. همچنین بازه قابل ذخیره‌سازی این دو نوع یکسان نیست. اگر به ذخیره تاریخ‌های دورتر از بازه TIMESTAMP نیاز دارید، DATETIME را بررسی کنید.

### سایر انواع مفید

- `BOOLEAN` یا `BOOL`: در MySQL نام مستعار `TINYINT(1)` است؛ معمولاً صفر و یک ذخیره می‌شود.
- `JSON`: برای داده‌های ساختاریافته انعطاف‌پذیر در قالب JSON.
- `ENUM`: انتخاب یک مقدار از فهرست تعریف‌شده؛ برای مقادیر ثابت و محدود مناسب است، ولی برای دسته‌بندی‌هایی که مرتب تغییر می‌کنند معمولاً جدول مرجع انعطاف بیشتری دارد.

## ۳. Constraintهای مهم

| Constraint | مفهوم | نمونه کاربرد |
|---|---|---|
| `NOT NULL` | مقدار خالی مجاز نیست | نام مشتری |
| `UNIQUE` | مقدار تکراری مجاز نیست | ایمیل |
| `PRIMARY KEY` | شناسه یکتای رکورد | customer_id |
| `FOREIGN KEY` | ارجاع به جدول مرتبط | customer_id در orders |
| `DEFAULT` | مقدار پیش‌فرض | زمان ایجاد |
| `AUTO_INCREMENT` | تولید شناسه افزایشی | id |

مثال:

```sql
CREATE TABLE customers (
    customer_id BIGINT UNSIGNED AUTO_INCREMENT,
    full_name VARCHAR(120) NOT NULL,
    email VARCHAR(160) NOT NULL UNIQUE,
    phone VARCHAR(20),
    city VARCHAR(80),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (customer_id)
) ENGINE = InnoDB;
```

## ۴. مشاهده ساختار جدول

```sql
DESCRIBE customers;
```

یا:

```sql
SHOW CREATE TABLE customers;
```

دستور دوم تعریف کامل جدول، شامل Constraintها و تنظیمات آن را نمایش می‌دهد.

## ۵. چند اصل طراحی برای تحلیل داده

1. هر ستون یک مفهوم مشخص داشته باشد؛ ستون `customer_info` که نام، شهر و شماره تلفن را در یک متن نگه می‌دارد تحلیل را دشوار می‌کند.
2. برای مبلغ از نوع دقیق مانند `DECIMAL` استفاده کنید.
3. کدهایی مانند تلفن، کد پستی و شناسه ملی را بدون نیاز به محاسبات عددی، به‌صورت متن ذخیره کنید.
4. برای هر جدول یک کلید اصلی تعریف کنید.
5. نام ستون‌ها را معنادار و یکدست انتخاب کنید.
6. مقادیر ناموجود را با `NULL` اشتباه نگیرید؛ صفر، رشته خالی و NULL مفهوم یکسانی ندارند.

## تمرین عملی

جدولی به نام `products` بسازید که شامل این ستون‌ها باشد:

| ستون | نوع پیشنهادی | قاعده |
|---|---|---|
| product_id | BIGINT UNSIGNED | کلید اصلی و افزایشی |
| product_name | VARCHAR(120) | اجباری |
| sku | VARCHAR(40) | یکتا |
| price | DECIMAL(12,2) | اجباری و نامنفی |
| stock_quantity | INT UNSIGNED | مقدار پیش‌فرض صفر |
| created_at | DATETIME | مقدار پیش‌فرض زمان فعلی |

پس از ساخت، با `DESCRIBE` و `SHOW CREATE TABLE` ساختار آن را بررسی کنید.

## جمع‌بندی

نوع داده تعیین می‌کند ستون چه مقادیری را بپذیرد؛ Constraintها قواعد اعتبار داده را اعمال می‌کنند. طراحی درست جدول از همان ابتدا، بخش مهمی از کیفیت تحلیل‌های بعدی است.
