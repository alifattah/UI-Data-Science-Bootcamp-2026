# درس ۲ — INNER JOIN؛ اتصال رکوردهای متناظر

اطلاعات کسب‌وکار معمولاً بین چند جدول تقسیم می‌شود. برای مثال، جدول سفارش‌ها شناسه‌ی مشتری را نگه می‌دارد، اما نام و شهر مشتری در جدول دیگری قرار دارد. با JOIN این اطلاعات را بر اساس یک کلید مشترک به هم وصل می‌کنیم.

## ایده‌ی JOIN در یک تصویر

~~~mermaid
flowchart LR
    A["customers"] -->|"customer_id"| C["INNER JOIN"]
    B["orders"] -->|"customer_id"| C
    C --> D["فقط ردیف‌های دارای تطبیق"]
~~~

در `INNER JOIN` فقط ردیف‌هایی وارد نتیجه می‌شوند که شرط اتصال برایشان برقرار باشد. اگر رکوردی در یک طرف همتای مناسبی در طرف دیگر نداشته باشد، در نتیجه‌ی INNER JOIN نمایش داده نمی‌شود.

## ساختار پایه

~~~sql
SELECT
    c.customer_id,
    c.full_name,
    o.order_id,
    o.order_date
FROM customers AS c
INNER JOIN orders AS o
    ON o.customer_id = c.customer_id;
~~~

در MySQL، نوشتن `JOIN` به‌تنهایی معادل `INNER JOIN` است.

### اجزای Query

| بخش | نقش |
|---|---|
| `FROM customers AS c` | جدول اصلی و نام مستعار آن |
| `INNER JOIN orders AS o` | جدول دوم |
| `ON o.customer_id = c.customer_id` | شرط اتصال |
| `SELECT ...` | ستون‌هایی که در خروجی می‌خواهیم |

استفاده از Aliasهایی مانند `c` و `o` باعث کوتاه‌تر شدن Query می‌شود. وقتی چند جدول ستون‌هایی با نام یکسان دارند، پیشوند جدول از ابهام جلوگیری می‌کند.

## مثال اجرایی روی دیتابیس فروشگاه

برای دیدن نام مشتری کنار سفارش‌هایش:

~~~sql
SELECT
    o.order_id,
    c.full_name,
    c.city,
    o.order_date,
    o.status
FROM orders AS o
INNER JOIN customers AS c
    ON c.customer_id = o.customer_id
ORDER BY o.order_date;
~~~

خروجی، هر سفارش را همراه با اطلاعات مشتری صاحب آن نشان می‌دهد.

## چرا ممکن است تعداد ردیف‌ها بیشتر شود؟

رابطه‌ی `customers` و `orders` یک‌به‌چند است:

- هر سفارش متعلق به یک مشتری است.
- یک مشتری می‌تواند چند سفارش داشته باشد.

پس اگر یک مشتری سه سفارش داشته باشد، اطلاعات آن مشتری در سه ردیف نتیجه تکرار می‌شود. این تکرار در سطح سفارش طبیعی است.

برای اینکه نوع رابطه را بهتر ببینید:

~~~sql
SELECT
    c.customer_id,
    c.full_name,
    COUNT(o.order_id) AS order_count
FROM customers AS c
JOIN orders AS o
    ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.full_name
ORDER BY order_count DESC;
~~~

## اتصال با بیش از یک شرط

گاهی تنها شناسه برای اتصال کافی نیست. برای مثال، اگر جدول قیمت‌گذاری بر اساس محصول و منطقه باشد، ممکن است هر دو ستون در کلید اتصال نقش داشته باشند:

~~~sql
SELECT
    s.sale_id,
    p.price
FROM sales AS s
JOIN regional_prices AS p
    ON p.product_id = s.product_id
   AND p.region_code = s.region_code;
~~~

در چنین طراحی‌هایی باید مطمئن شوید ترکیب ستون‌های اتصال واقعاً رکورد متناظر را مشخص می‌کند.

## یک نکته مهم: شرط اتصال را با شرط فیلتر اشتباه نگیرید

- `ON` مشخص می‌کند دو جدول چگونه به هم مرتبط شوند.
- `WHERE` مشخص می‌کند کدام ردیف‌های نتیجه باقی بمانند.

در INNER JOIN بسیاری از شرط‌ها را می‌توان از نظر نتیجه بین ON و WHERE جابه‌جا کرد؛ اما در LEFT JOIN این جابه‌جایی می‌تواند معنای Query را تغییر دهد. در درس بعد این تفاوت را دقیق‌تر می‌بینیم.

## تمرین

1. شناسه سفارش، نام مشتری و شهر او را نمایش دهید.
2. فقط سفارش‌های با وضعیت `completed` را نگه دارید.
3. تعداد سفارش هر مشتری را محاسبه کنید.
4. نتیجه را به شکلی تغییر دهید که به‌جای جزئیات سفارش، فقط شهر و تعداد سفارش‌ها نمایش داده شود.
5. پیش از اجرای Query، تعداد تقریبی ردیف‌های خروجی را حدس بزنید و سپس با نتیجه مقایسه کنید.

## جمع‌بندی

- INNER JOIN فقط رکوردهای دارای تطبیق را نگه می‌دارد.
- اتصال باید بر اساس کلید یا ویژگی مشترک معتبر انجام شود.
- رابطه یک‌به‌چند باعث تکرار اطلاعات سمت یک در خروجی می‌شود.
- تعداد ردیف خروجی را همیشه با سطح تحلیل موردنظر خود مقایسه کنید.
